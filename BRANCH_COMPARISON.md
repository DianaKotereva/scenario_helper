# Сравнение локального состояния с последним коммитом GitHub

Дата: 20 сентября 2026 года.

## Результат

**Содержимое `src/` и `tools/` в сохранённом локальном снимке полностью совпадает с последней удалённой версией от 20 мая.** Это проверено сравнением Git-деревьев, включая локальную копию SGR и preprocessing. Коммиты имеют разную историю, но исходный код этих двух каталогов одинаковый.

Основные различия находятся в данных, конфигурации запуска, документации и двух файлах регрессионной проверки extraction-промптов, которые присутствуют только в майской ветке.

## Найденные проверки промптов

В майской ветке обнаружен [YAML с регрессионными проверками](https://github.com/DianaKotereva/scenario_helper/blob/c4474e9227869c90b5de9fc72339eeccd3747568/validation/extraction_prompt_checks.yaml) и [скрипт запуска](https://github.com/DianaKotereva/scenario_helper/blob/c4474e9227869c90b5de9fc72339eeccd3747568/scripts/check_extraction_prompt_rules.py).

В YAML семь проверок:

1. Гэлвэ не должен получать alias «Аэнарион».
2. Силанна должна присутствовать в батче глав 35–39.
3. Циандрос должен присутствовать в батче глав 100–104.
4. Не должна возникать ложная сущность вида «Лаурэфиндэ (ящер)».
5. Лаурэфиндэ не должна получать alias «Минратос».
6. Если есть Нарион, у него не должно быть alias «дядя Лаурэ».
7. Моркарк должен оставаться отдельной сущностью, без ошибочного объединения через aliases с Тху, Синденармо и Отомбаком.

Это подтверждает наличие специального набора проверок для подбора extraction-промптов. Сам набор не содержит пяти вариантов промпта и не доказывает, сколько вариантов сравнивали. Скрипт проверяет готовые batch payloads и не запускает LLM.

Оба файла оставлены в майской ветке: при создании резервного снимка изменения двух веток не объединялись. Их можно перенести отдельным последующим изменением, сохранив возможность проверить эффект.

## Что сохранено и что осталось локальным

Коммит снимка включает 253 новых/изменённых/удалённых файла относительно исходного локального HEAD: ранее подготовленные данные, текущие изменения кода, локальный SGR, конфигурацию и архитектурный разбор.

Новые `processed_data/all_langchain_chunks.pkl` и `processed_data/bookgraph.pkl` сохраняются через уже настроенный Git LFS. Их общий размер — 18 474 197 байт. JSON/JSONL сохраняются обычным Git.

`.env`, секреты и неотслеживаемые файлы, исключённые действующим `.gitignore`, в снимок не добавлялись. Исключённые каталоги результатов экспериментов, логов и локального состояния остаются на диске; эта ветка не является полным архивом всех байтов рабочей папки. Соседние `ideas/`, `Hyper-Extract/`, `open-notebook/` и отдельный `sgr-agent-core/` находятся за границей основного репозитория и этим коммитом не публикуются.

Перед изменением staging сохранена резервная копия исходного Git index и списка изменений в `.git/codex-backups/before-local-workspace-20260920/`.

## Выполненные проверки

- Получены актуальные удалённые refs через `git fetch`; определена наиболее свежая ветка.
- Проверены новые и изменённые файлы на известные значения секретов из локальных `.env` и характерные форматы ключей; совпадений не обнаружено.
- `.env` и `tools/.env` отсутствуют в составе коммита.
- Синтаксически разобраны 59 добавленных/изменённых Python-файлов: ошибок не найдено.
- `git diff --cached --quiet <майский ref> -- src tools` до создания коммита подтвердил идентичность двух каталогов.
- Создание снимка не сопровождалось запуском extraction, LLM или переиндексацией.

## Как повторить сравнение

Из корня `scenatio_helper`:

```powershell
# Точное сравнение содержимого двух зафиксированных снимков.
git diff --stat c4474e9227869c90b5de9fc72339eeccd3747568 f5df5d402614b5930300cbe50164e933ba830e77

# Должен вернуть пустой diff.
git diff c4474e9227869c90b5de9fc72339eeccd3747568 f5df5d402614b5930300cbe50164e933ba830e77 -- src tools

# Различия за пределами больших данных.
git diff --name-status c4474e9227869c90b5de9fc72339eeccd3747568 f5df5d402614b5930300cbe50164e933ba830e77 -- . ':!processed_data'
```

[Сравнение снимков на GitHub](https://github.com/DianaKotereva/scenario_helper/compare/c4474e9227869c90b5de9fc72339eeccd3747568..f5df5d402614b5930300cbe50164e933ba830e77).

Для сравнения конечных состояний используются две точки (`base..head`). Сравнение через три точки показывает изменения от общего предка: из-за разной истории оно может представить совпадающий SGR-код как добавление и затруднить чтение результата.
